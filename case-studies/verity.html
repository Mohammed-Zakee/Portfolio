SOLO PROJECT / BUSINESS INFORMATION & REVIEW ANALYTICS

Verity

Turning scattered reviews into an explorable business picture.

A solo project designed to help users collect Google Maps business information and images more easily, with a review-analysis workflow and visual reporting interface.

01 / THE PROBLEM

What needed solving?

A star rating alone does not explain what customers repeatedly praise or complain about. Reading individual reviews is slow; a useful exploration tool needs to bring themes, sentiment, and changes over time together.

02 / IMPLEMENTATION

How the system fits together.

The repository contains a Next.js interface, a Flask API, and a Playwright collection pipeline. The analysis layer produces sentiment labels, theme counts, recurring negative terms, word frequencies, and a rating timeline. The Next.js frontend includes JSON, CSV, Excel, and PDF export paths.

03 / ENGINEERING CHOICES

The choices and their trade-offs.

An explainable NLP baseline

The current engine uses positive and negative word sets, immediate-word negation, and fixed thresholds. It is small and inspectable, with no model-service dependency; it cannot interpret language as broadly as a contextual model.

Separate presentation from collection

The frontend talks to a Flask API. This keeps browser-driven collection outside the interface, while making deployment configuration and backend availability part of the end-to-end experience.

Multiple ways to inspect the same data

Themes, individual reviews, word frequency, and time-based summaries give context beyond a single score. Export paths make the analysis portable.

04 / EVIDENCE

What is demonstrated.

8 focused sentiment checks passed
4 frontend export formats in source
Live public landing interface inspected

The public landing interface loads, and the repository contains the collection, analysis, dashboard, and export implementations. Eight focused checks of the sentiment function were run for this case study; they confirm basic behavior, not real-world classification accuracy.

Limitations

  • Keyword rules can miss sarcasm, context, and multilingual reviews. No independently measured accuracy figure is available.
  • Live collection depends on the external site and backend environment; loading the frontend does not establish that every end-to-end search succeeds.
  • Relative review dates are grouped approximately. Scraped reviews are a sample, not a complete or unbiased view of a business.

05 / NEXT STEPS

What I would improve next.

  1. Build a labeled review set and report precision, recall, and error examples.
  2. Compare a contextual model with the rule-based baseline, including latency and multilingual cases.
  3. Add deterministic collection fixtures, clearer empty/error states, and end-to-end deployment checks.
